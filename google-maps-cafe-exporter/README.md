# Экспорт кафе из Google Maps

Локальный сайт открывает обычную выдачу Google Maps в Chromium, а не использует Places API. Он собирает карточки кафе в заданном радиусе и проверяет их публичные сайты для поиска e-mail и ссылок на соцсети. Координаты центра города определяются одним бесплатным запросом к OpenStreetMap Nominatim без ключа; это нужно только для точного радиусного фильтра.

## Запуск

Нужен Node.js 20+.

```powershell
cd D:\proekty\landos\google-maps-cafe-exporter
npm install
npx playwright install chromium
npm start
```

Откройте `http://localhost:3210`.

При первом запуске Chromium отображается на экране. Входить в Google-аккаунт не нужно: скрипт сам выбирает на странице Google приватный вариант «Отклонить все» и сохраняет это решение в локальном профиле `.maps-browser-profile`. Не вводите пароль Google и не решайте капчу через сторонние сервисы. Если Google показывает капчу или сообщение о необычной активности, скрипт прекращает работу и сообщает об этом.

## Что выгружается

- название, адрес, средняя оценка, количество отзывов, ссылка на Google Maps и на официальный сайт;
- e-mail и ссылки Instagram, Facebook, VK, Telegram, TikTok, YouTube, X/Twitter и LinkedIn — только если они опубликованы на сайте заведения; ссылки «поделиться» и пустые страницы соцсетей отбрасываются;
- текстовая дата самого нового отзыва: скрипт открывает вкладку «Отзывы», выбирает «Самые релевантные → Сначала новые» и берёт дату первого отзыва.

## Важные ограничения

- Google Maps не обещает полный список выдачи через свой интерфейс. Скрипт проходит несколько точек в радиусе, убирает дубли и ограничивает число результатов; плотные районы могут требовать несколько запусков с меньшим радиусом.
- В выдачу попадают только карточки с подтверждённой категорией общепита из Google Maps: кафе, рестораны, бары, пекарни, кондитерские, джелатерии, фастфуд и аналогичные типы. Площади, памятники, музеи, отели и прочие не-food объекты отсекаются до открытия сайта и разбора ассетов. Тип дополнительно сверяется после открытия карточки.
- Дата отзыва возвращается в том виде, в каком она показана в Maps (например, «2 недели назад»), и только после проверки, что выбор сортировки переключился на «Сначала новые» и первая карточка отзыва загрузилась. Карточки Maps обрабатываются последовательно: это медленнее, зато уменьшает пропуски отзывов при медленной загрузке интерфейса.
- E-mail и соцсети не являются полями Google Maps. Они извлекаются с публичного сайта без обхода доступа, поэтому могут отсутствовать.
- Соблюдайте условия Google Maps и правила сайтов, которые проверяете; инструмент не обходит капчи, авторизацию, ограничения частоты или запреты доступа.

## Настройка лимитов

Скопируйте `.env.example` в `.env` и при необходимости уменьшите лимиты. Большой радиус означает больше переходов по страницам и выше вероятность, что Google ограничит автоматические запросы.

## Проверка меню для лендинга

Для каждого кафе со сценарием «Есть меню на сайте» извлечение выполняется не по одной ссылке, а в три полных прохода:

1. На каждом проходе проверяются главная страница, ссылки на меню, страницы конкретного заведения (`bar`, `restaurant`, `food`, `dining`), вложенные ссылки, PDF и другие документы, а также оригиналы изображений из галерей.
2. Если обычный HTML не дал подтверждённых позиций, страницы дополнительно открываются в браузере в desktop- и mobile-режимах — это нужно для меню, загружаемых JavaScript или по QR-ссылке.
3. PDF разбираются с сохранением строк; для сканов используется OCR. В landing попадают только позиции, подтверждённые текстом, PDF или OCR, и только через `menu.items` в сохранённом разборе.
4. Декоративные картинки, заголовки сайта и неуверенный OCR отбрасываются. Инструмент не придумывает блюда: если после всех проходов сайт не отдаёт читаемые позиции, это явно остаётся предупреждением, а не превращается в ложное меню.

## Проверка графических ассетов для лендинга

Логотипы, фотографии карточки Google Maps и фотографии блюд проверяются на двух уровнях перед публикацией:

1. При извлечении сервер повторно загружает каждый кандидат, проверяет HTTP-ответ, MIME-тип, размер и декодирование изображения. SVG дополнительно проверяется на наличие отображаемых векторных элементов и контраст с фоном Classic Light.
2. Если SVG светлый (например, состоит только из белых контуров), лендинг автоматически размещает его на контрастной тёмной подложке, а не оставляет невидимым на белой шапке.
3. Сам Classic Light слушает событие загрузки каждого графического файла. Если CDN, изображение или SVG перестали отдаваться в браузере, ошибочный элемент не остаётся пустым: для логотипа показывается текстовый брендовый fallback, а необязательные фотографии скрываются.

Таким образом в сохранённом разборе фиксируется как техническая пригодность файла, так и необходимость контрастной подложки; URL сам по себе больше не считается достаточным подтверждением ассета.
